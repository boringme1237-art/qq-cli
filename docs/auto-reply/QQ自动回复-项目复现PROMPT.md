# QQ 工作台自动回复系统 · 项目复现 PROMPT 集

> ℹ️ 本文为真实使用案例的**脱敏版**：QQ 号、群号、群名、人名与本机路径均已替换为占位符。


> 用途：把 2026-09-07～09-08 建成的这套系统完整沉淀为**可复用的 prompt**。
> 任何人（或任何一次新会话）拿到下面的 prompt，都能在同类 Windows + QQ NT 环境上从零重建同一套系统。
> 所有聊天数据全程本地处理，不联网、不外传。

## 0. 主 PROMPT（一句话复现整个系统）

```
我要在本机搭建一套「QQ 工作台自动回复 + 未回复提醒」系统，全程本地、只读、不发外网。请按以下阶段执行：

【P1 安装与审计】安装本地 QQ 聊天数据读取工具 qq-cli（GitHub: boringme1237-art/qq-cli），
安装前先逐文件做安全审查，必须满足三条红线：
  1) 源码不得含任何联网/上传代码（无 requests/urllib/socket/http，无外发行为）；
  2) QQ 源数据库（文档\Tencent Files\<QQ号>\nt_qq\nt_db\*.db）只能只读打开，
     所有 SQL 只能是 SELECT，解密副本只允许写到系统临时目录；
  3) 不得触碰微信、其他腾讯应用或系统其他位置的数据与配置。
用独立 venv 安装（不污染全局 Python），依赖走国内镜像。

【P2 账号确认】先运行 accounts 列出本机所有 QQ 号，**不要替我猜**，等我确认用哪个；
之后所有命令都带 --account 指定。

【P3 风格学习】读取我在指定群的全部历史发言，归纳我的回复风格。
注意：QQ 的引用回复消息，工具默认取"最长文本片段"，取到的是客户原话而非我的答复——
必须写识别逻辑把"引用原文"与"我的答复"拆开，否则会把客户的话误当我的风格。
产出：风格手册（含场景模板、转人工清单）+ 可一键复制的快捷回复面板 HTML。

【P4 问题分类】写一个分类器判断哪些消息是"问题/请求消息"，必须忽略：
"谢谢/可以了/收到/好的"等无请求的确认语、以及对方表示"我自己处理"的消息。
先用历史消息干跑验证准确率，误判要修规则，不要直接上线。

【P5 监控提醒】每 20 秒轮询一次本地库，发现问题消息就记录待办；
超过 30 分钟我没做二次回复，就弹窗提醒我（可能是我忘了）。

【P6 自动回复】
  方案A：在条件满足时自动往群里发固定占位话术（"收到，老师，马上处理"），
        仅限工作日 08:30–17:30，且只在群窗口是当前打开会话、且我键盘空闲 3 秒以上时才发。
  方案B：保留话术链路——发现问题就弹窗提醒 + 给出符合我风格的话术，供我一键复制/手动发送。

【硬约束，全程不得违反】
  - 全程本地，禁止把聊天内容粘贴或上传到任何网页、外部服务；
  - 不得写入/修改源数据库，不得删除密钥文件；
  - 只发固定占位话术，绝不自动回答实质性内容（审核结果/排查结论/数据变更一律转人工）；
  - 宁可只回"稍等"，绝不编造结论。
```

## 1. P1 · 安装与安全审计

```
帮我安装 qq-cli（https://github.com/boringme1237-art/qq-cli，克隆或解压 Release zip 均可），
不要重复安装其他工具。整个过程自动完成；需要我授权（读进程内存、浏览器登录）或操作电脑界面时提醒我。

安装前先做一次安全检查，逐文件确认以下红线，任何一条不满足就停下来告诉我：
1. 源码不得包含任何联网/上传代码：不允许出现 requests、urllib、socket、http 等网络库，
   不允许有任何把聊天数据、密钥或统计结果发送到外部的行为。
2. 对 QQ 源数据库（文档\Tencent Files\<QQ号>\nt_qq\nt_db\*.db）只能只读打开，
   不得写入、修改、删除、重命名任何源文件；所有 SQL 只能是 SELECT；解密副本只允许写到系统临时目录。
3. 不得触碰微信、其他腾讯应用或系统其他位置的数据与配置。

然后阅读 README.md、docs\qqnt-database-notes.md、skills\qq-local-reader\SKILL.md，
确认依赖（Windows 10/11、Python 3.10+、QQ NT 已登录运行）、安装步骤与风险后再开始。

安装约定：
- 用独立 venv，不污染全局 Python；
- 首次 init 需要读取 QQ.exe 进程内存提取数据库密钥，是纯读取（不注入不 Hook 不写入），
  杀毒软件可能告警属预期；
- 密钥明文保存在 ~/.qq-cli/keys/，属敏感文件：不得复制、上传或写入任何公开位置；
- 导出的聊天记录含个人敏感信息，导出位置先问我。
```

**审计结论（本机实测）**：三条红线全部通过。关键点——`sqlite3.connect` 全仓只出现 1 次，连的是临时副本且带 `mode=ro`；源库只用 `open(..., "rb")` + `os.path.exists`/`getmtime`，从不对源库建连接（避免生成 `-wal`/`-shm`）。依赖仅 `click` + `pycryptodome`，无夹带。

**踩坑**：GitHub 在本机不可达时，可用 `git blob SHA1` 做字节级复核——GitHub tree API 返回每个文件的 blob 哈希，本地按 `sha1("blob " + len + "\0" + 内容)` 重算比对，即可在无法直连的情况下验证文件与远端 commit 逐字节相同。另：早期 Release 包扩展名虽为 `.zip` 实为 tar 打包，`zipfile` 报 `BadZipFile` 时改用 `tar -xf` 解压即可（当前 Release 已改为标准 zip）。

## 3. P3 · 风格学习（含关键陷阱）

```
读取我在群「<群名>」的全部历史发言，总结我的回复风格，并据此做一套自动回复。

⚠️ 关键陷阱：我的消息 60% 是"引用回复"（消息类型 9）。工具提取消息时取**最长文本片段**，
而最长片段恰好是"客户原话 + @我"——直接拿来分析，结论会变成"我的风格是'老师麻烦审核下供应商'"。
必须写识别逻辑：引用原文因嵌套会重复出现，只出现一次的短片段才是我的真实答复。请务必拆开。

产出两样东西：
1. 风格手册 .md：风格规则 + 11 类场景模板 + 必须转人工的清单；
2. 快捷回复面板 .html：分类排好、可搜索、点一下就复制。
```

**归纳出的风格（222 条真实发言）**：
- **三段式**：`好的，请稍等，老师` →（去系统操作）→ `已审核 / 已解锁`（极短完成态）
- **"老师"是万能称呼**，位置灵活：句首/句中/句尾均可
- **极短**，多数 4~12 字，句尾基本无句号
- **完成态固定"已X"或"X了"**：已审核 / 已解锁 / 已重置 / 已新增 / 解锁了老师
- **语气词呢/哦/呀**：`我这边查一下呢`、`麻烦您自己启用一下哦`
- **同一句话从不重复**：仅"稍等"就有 16 种变体（刻意轮换，不像机器人）
- **排查用反问不解释原理**：`你们是从哪个入口进去的呢`、`你刷新下试试呢`
- **从不**：发长段落、堆书面敬语（"非常抱歉给您带来不便"一次没用过）、承诺具体时间点

## 4. P4 · 问题消息分类器

```
写一个分类器判断哪些消息是"问题/请求消息"，先用最近 48~72 小时历史消息**干跑**验证，
把判为"是"和"否"的两组都打出来让我核对；有误判就修规则，确认准确率后再上线。

必须忽略：
- "谢谢/可以了/收到/好的/嗯嗯/辛苦了"等无请求的确认语；
- 对方表示"我自己处理"的消息（我去问一下 / 我确认下 / 我联系…）；
- 纯表情、系统提示、/download 文件链接；
- 很短（≤6 字）且无任何请求信号的消息。

判定信号：请求动词（麻烦/审核/解锁/重置/添加/查询…）、问题描述（不行/报错/进不去/选不了…）、问号。
```

**实测**：干跑 6/6 全对——7 条真实请求全命中，"谢谢""可以了""收到"全正确忽略。唯一误判（客户说"我去问一下"被当请求）已通过 `SELF_HANDLE` 规则修掉。

## 5. P5 · 实时监控与 30 分钟提醒

```
写一个常驻监控脚本 qq_watch.py：
- 每 20 秒读一次本地库，判断新问题，写入待办状态（JSON）；
- 超过 30 分钟我没做二次回复，就弹 Windows 通知提醒我（我可能是忘了）；
- 二次回复的判定：在该问题之后 6 小时窗口内，我发的消息里出现对方的昵称关键字；
- 由 Windows 计划任务托管进程，掉线能自愈。

命令集：init / scan / remind / list / ack / dry / watch / watchdog / status / sendtest。
```

**架构决策**：监控进程**必须由计划任务直接托管**（`pythonw.exe qq_watch.py watch`）。从终端/脚本里 fork 的子进程会随会话结束被杀——实测两次均失败。计划任务方式跨会话存活已验证。

## 6. P6 · 自动回复（方案 A + 方案 B）

```
【方案A】自动发固定占位话术"收到，老师，马上处理"（普通消息）：
  - 仅工作日 08:30–17:30；
  - 群窗口必须是 QQ 当前打开的会话（QQ NT 单窗口架构，窗口标题须精确匹配群名），否则排队并提醒我；
  - 我键盘必须空闲满 3 秒才发，绝不抢键盘；
  - 发送前后保存并还原剪贴板；每小时最多 20 条；每次发送写日志。

【方案B】保留话术链路：发现问题就弹窗提醒 + 按我的风格给出话术，供我一键复制/手动发送。
  另有一个每小时运行的 AI 自动化任务，负责按风格起草**实质性**回复建议。
```

**发送实现**：GUI 模拟按键（`qq_sender.py`）——窗口定位 → 空闲检测 → 剪贴板写入 → Ctrl+V → Enter。腾讯不提供个人 QQ 官方发消息 API；第三方机器人（go-cqhttp / NapCat）靠逆向协议，封号风险高，475+ 人的客户群不予采用。

**64 位指针 bug**：`GlobalLock` 返回指针在 64 位下会被 ctypes 默认截断为 32 位，必须显式声明 `restype`/`argtypes` 为 `ctypes.c_void_p`，否则剪贴板读写出乱码。

## 7. 引用回复的可行性结论（重要，勿重复踩坑）

```
需求：自动回复必须是"引用回复"（引用客户那条问题消息）。

结论：QQ NT 上**做不到**，已穷尽验证：
1. QQ NT 是 Chromium/Electron 内核，每个会话一个独立 Chrome_WidgetWin_1 顶层窗口；
2. 置前台后 UIA 控件树只有匿名 PaneControl 空壳，读不到任何消息文本元素
   （渲染器无障碍被关闭）→ 无法定位"某一条消息"来触发引用；
3. 右键菜单也不是原生菜单（无 #32768 类窗口），是 HTML 绘制，同样无法自动化定位；
4. 唯一出路是用 --force-renderer-accessibility 重启 QQ 强制开启无障碍——**实测 QQ 直接报错无法启动**。
⚠️ 教训：不要给 QQ 加命令行参数、不要从工具沙箱代启动 QQ。需要重启 QQ 一律请用户手动操作。
```

## 9. 常用命令

```bash
cd <你的工作目录>
PY=<qq-cli 安装目录>\.venv\Scripts\python.exe
PYTHONIOENCODING=utf-8

$PY qq_watch.py status        # 监控是否在跑
$PY qq_watch.py list          # 当前待处理
$PY qq_watch.py scan          # 手动扫一次（会顺带自动回复）
$PY qq_watch.py remind        # 手动检查超时未回复
$PY qq_watch.py ack all       # 全部销单
$PY qq_watch.py dry 72        # 干跑：看分类准不准，不写状态
$PY qq_watch.py sendtest dry  # 演练发送：只定位窗口不真发
$PY qq_watch.py stop          # 停止（计划任务会重新拉起）
```

彻底关闭：任务计划程序里禁用/删除 **「QQ群实时监控」**。
