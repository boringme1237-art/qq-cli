## 一、现在是怎么工作的

```
每 20 秒
  └─ 读本地聊天库（只读）
      └─ 判断是不是"问题消息"
          ├─ 是 → 你空闲时自动回复「收到，老师，马上处理」
          │       并记入待办，开始计时
          └─ 否（谢谢 / 可以了 / 收到 / 我自己处理…）→ 忽略

30 分钟后
  └─ 检查你有没有对这个人有二次回复
      ├─ 有 → 自动销单
      └─ 没有 → 弹窗 + 提醒你："已等待 X 分钟未见回复"
```

**实时性**：20 秒轮询，基本等同实时（QQ 消息落本地库本身也有秒级延迟）。

## 二、必须知道的四个限制

### 1. 没有"官方接口"这回事
腾讯不提供个人 QQ 的官方发消息 API。市面上的第三方机器人（go-cqhttp / NapCat 等）
靠逆向协议，**封号风险很高**，我没有用、也不建议用。
现在这套是**模拟按键**——相当于有个人帮你在 QQ 窗口里打字回车，走的是官方客户端。

### 2. 群窗口必须是 QQ 当前打开的会话
QQ NT 每个会话是一个**独立窗口**，窗口标题 = 会话名。只有标题**精确等于**群名时才会发送，
两个群各自判断，互不干扰。
该群的窗口没打开（或最小化了）时，消息会**排队**，等窗口出现再补发，同时弹窗提醒你。
→ 建议：**让两个群的窗口都开着**（不用置顶，开着即可），效果最好。

### 3. 你正在打字时不会抢键盘
发送前会检测你的空闲时间，**必须空闲满 3 秒**才发；不满足就推迟到下一轮（20 秒后）重试。

### 4. 非工作时间不自动发送
周一至周五 **08:30–17:30** 之外只记录、不发送，也不会去抢你的窗口。

### 5. 自动发的是普通消息，不是"引用回复"
QQ NT 的消息控件被无障碍树屏蔽，无法定位到具体某条消息去触发引用（详见
`QQ自动回复-项目复现PROMPT.md` 第 7 节）。所以自动回复是**普通消息**；
需要引用客户原话时，请用快捷回复面板手动发。

## 三、安全边界

| 会做 | 不会做 |
|---|---|
| 只发固定话术「收到，老师，马上处理」 | 不会自动回答任何实质内容 |
| 只在标题精确匹配的群窗口发 | 不会在别的窗口/会话乱发 |
| 发送前后保存并还原剪贴板 | 不会碰你的聊天文件（只读） |
| 每小时最多发 20 条，防失控 | 不会删改源数据库、不会动密钥 |

**实质性回答（审核结果、排查结论、驳回说明等）永远交给你**——那需要真实操作系统，
我没有权限，也不会替你编。

## 四、常用命令

在 `<你的工作目录>` 下执行，
解释器用 `<qq-cli 安装目录>\.venv\Scripts\python.exe`：

| 命令 | 作用 |
|---|---|
| `qq_watch.py status` | 看监控是否在跑 |
| `qq_watch.py list` | 看当前待处理的问题 |
| `qq_watch.py scan` | 手动扫一次（会顺带自动回复） |
| `qq_watch.py remind` | 手动检查超时未回复 |
| `qq_watch.py ack all` | 把待办全部标记已处理 |
| `qq_watch.py ack <id>` | 只消掉某一条（id 见 list 输出） |
| `qq_watch.py sendtest dry` | **演练**：只定位窗口不真发，用来确认一切正常 |
| `qq_watch.py stop` | 停止监控（计划任务 10 分钟内会重新拉起） |
| `qq_watch.py dry 72` | 回顾最近 72 小时，看分类判断得准不准，不写状态 |

**彻底关掉**：在"任务计划程序"里禁用/删除任务 **「QQ群实时监控」**。

## 五、想改什么，改 `qq_watch.py` 顶部

```python
GROUPS = {                      # 双群监控：群号 → 窗口标题（必须精确匹配）
    <群号A>: "示例客服群A",
    <群号B>: "示例客服群B",
}
ME               = <你的QQ号>   # 你的工作台账号
AUTO_REPLY       = "收到，老师，马上处理"   # 自动回复的话术
ROTATE           = False    # True = 在 4 种"收到类"话术间轮换，更像人
REMIND_AFTER_MIN = 30       # 多少分钟没二次回复就提醒你
POLL_SEC         = 20       # 轮询间隔（秒）
IDLE_MIN_MS      = 3000     # 至少空闲这么久才发送（防抢键盘）
MAX_SEND_PER_HOUR= 20       # 每小时发送上限
AUTO_SEND        = True     # False = 只提醒，永不自动发（退回纯方案B）
DRY_RUN          = False    # True = 只演练不真发
WORK_START_MIN   = 8*60+30  # 工作时间 08:30
WORK_END_MIN     = 17*60+30 # 工作时间 17:30（周一至周五）
```

改完执行 `qq_watch.py stop`，等计划任务（10 分钟内）重新拉起即可生效。

## 五之二、方案 A / B 同时在跑

- **方案 A（自动发）**：命中问题消息 → 满足时间窗 + 窗口在 + 键盘空闲 → 自动发固定话术。
- **方案 B（话术链路，始终保留）**：
  - 「QQ快捷回复面板.html」——11 类场景、60+ 条话术，可搜索一键复制；
  - 每小时的 AI 自动化任务——按你的风格起草**实质性**回复建议（审核结果、排查结论等），
    供你手动发；
  - 30 分钟未二次回复的弹窗提醒。

两者互补：A 负责"秒回占位"，B 负责"说得对"。
